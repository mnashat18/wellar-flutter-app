# Mobile Fix Priority and Regression Gates

**Decision:** audit only; no fixes were implemented. The ordering below minimizes duplicate AI processing and employee data exposure while preserving the deployed API contract in the first phase.

| Rank | Priority | Minimal change | Key files | Acceptance / regression gate |
|---:|---|---|---|---|
| 1 | P0 | Stop interpreting timeout/result absence as a new scan. Add “resume/check existing scan” and reconcile existing status/result before offering a deliberate new scan. ## Release gates (future work; no release authorized here)

- API compatibility contract tests confirm existing Directus collections, `/process` path, and request payload remain unchanged for mobile-only changes.
- Idempotency behavior is confirmed by backend owner and response-loss tests; otherwise dispatch remains “uncertain—reconcile,” never automatic replay.
- P0/P1 regression gates above pass on Android and iOS, including process restart and low-connectivity paths.
- Privacy owner signs off deployed authorization, media retention, log redaction, crash-reporting fields and employee consent/notice.
- Load test separately defines 2,000 total employees versus peak concurrent scans, then validates API/AI service capacity with backend owners.

No application changes, commits, or releases were made as part of this audit.
